# 运行与治理

## 队列与资源

- `TOOLDECK_WORKER_CONCURRENCY=2`：全局运行并发。
- `TOOLDECK_USER_CONCURRENCY=1`：单个调用者并发，同一用户的会话和 API Key 合并计数；OAuth 按其认证主体计数，匿名用户按浏览器身份计数。
- `TOOLDECK_BUILD_CONCURRENCY=1`：独立构建并发。
- 三个配置都接受 1–64；无效值拒绝启动。群晖建议从 2/1/1 开始。
- 工具清单支持 `execution.max_concurrency`（0 表示不限，最高 64）。同作者同名称的各版本共享限制，使用各版本中最严格的非零值。
- 原子领取在保存成功后才启动；用户或工具达到上限时会跳过该任务，调度其他可运行任务。取消响应不代表执行槽已经释放，槽位在执行清理完成后释放。
- 队列上限仍为 100，同步 HTTP 最长等待仍为 20 秒。运行进程退出不重放运行中任务，避免重复调用第三方服务；取消中断保留为 `cancel_failed`。
- 平台的 512 MiB 内存限制不包含所有工具容器。运行容器按各工具声明限制，构建容器各有 1 GiB 限制，增加并发前应检查宿主机总容量。

## SQLite 迁移、备份与回滚

数据目录首次启动时会建立 `state.db`，使用 WAL 和 FULL 同步。工具、运行、用户、文件等实体分别保存为记录，一次业务保存使用事务，只更新有变化的记录。当前业务层仍使用进程内状态和锁，`controller.lock` 禁止两个控制服务同时打开同一目录；这不是多控制节点架构。`StateBackend` 为后续数据库实现保留接口。

如果没有已完成的数据库，程序会读取原 `state.json`，将字节完全相同的副本写入 `state.json.pre-sqlite.bak`，再导入数据库。原 JSON 不修改。无效 JSON、备份冲突或写入失败会阻止启动；数据库事务未成功时，下次仍可重试导入。数据库一旦初始化成功，旧 JSON 不再参与读取和保存。

请在升级前停止旧服务并备份整个数据目录和 `TOOLDECK_MASTER_KEY`。不要让旧 JSON 版本和新 SQLite 版本同时访问目录。保留密钥，才能解密已有凭证。

运行期间可以导出一致的 JSON 快照，不覆盖已有目标文件：

```sh
docker compose exec platform tooldeck-state-export --data /data --output /data/rollback-20260921.json
```

本地开发也可使用 `go run ./cmd/state-export --data /path/to/data --output /path/to/new-snapshot.json`。导出器只读数据库，不触发重启恢复。

回退步骤：停止新服务，另存当前完整数据目录，将最新导出 JSON 复制为回退目录的 `state.json`，在回退目录启动旧版本并使用相同主密钥。`state.json.pre-sqlite.bak` 只包含升级时的数据，不能代替升级后的最新导出。恢复新版本时在新的恢复目录导入快照；不要将旧快照覆盖到仍有 `state.db` 的工作目录。离线备份应包含 `state.db`、`state.db-wal`、`state.db-shm`（存在时）及文件目录，不能只复制正在写入的主数据库文件。

## 运行监控和审计

管理员的“运行与治理”页展示排队/执行/构建数量、平均等待和当前最长等待、成功率、P95 耗时、当前各版本构建失败率、最终回调失败率和数据盘剩余空间。

- 运行指标按当前保留的全部任务计算；限额命中是调度扫描阻挡次数，自进程启动累计。
- `GET /api/v1/metrics` 返回 JSON。设置 `TOOLDECK_PROMETHEUS=true` 后，可用 `?format=prometheus` 获取指标，仍需管理员会话认证。
- `GET /api/v1/audit?page=1&actor=...` 分页查询审计。最近 10,000 条保存在数据库，结构化 JSON 同时写入 stderr，长期归档应由日志系统接管。
- 审计记录操作者、路由操作、对象 ID、连接来源 IP、HTTP 结果和通用错误摘要。反向代理部署显示实际连接的代理地址，不盲信客户端的转发头。不采集请求体、查询字符串、认证头、密钥值或原始业务错误。

## 存储治理

“存储治理”页预览本地目录和可清理对象。只允许处理超过 24 小时、未被工具、运行历史、文件记录或活跃任务引用的内容。提交时重新扫描和比较预览令牌；引用变化会拒绝清理。文件移入数据目录的 `quarantine/<批次>/`，文件名中的 `__` 对应原路径分隔符。恢复前停止服务并核对原路径不存在，然后移动回原目录。

移入恢复区不会释放磁盘空间；确认不再需要后，由管理员离线备份或删除恢复区批次。程序不会自动永久删除恢复区。

站点、每用户、每工具配额计入保留的工具包、构建产物和输入/输出文件（含 BOS 文件），默认 0 表示不限。上传和产物入库时包含并行操作的预留量，防止并发超额。它不替代宿主机磁盘限制，数据库、临时工作目录、恢复区、Docker 镜像和 BuildKit 缓存不计入这些逻辑配额。

“Docker 资源”页仅扫描本实例标签标记的容器和运行镜像，执行清理前再次检查。只删除超过 24 小时的停止容器和闲置镜像，不使用强制删除，不操作其他实例、预置共享镜像或运行中的容器。旧版本未标记的 Docker 资源保留。共享 BuildKit 缓存没有可靠的项目归属，目前不自动清理，避免影响其他项目。

## 版本发布

“我的工具 → 版本发布”提供默认版本切换、清单对比、1–99% 灰度、停止灰度和回滚。默认版本记录独立于上传、构建和审核状态。第一次导入旧数据时选取当时最新的已发布版本；之后新版本审核通过不会替换已有默认版本。

灰度按工具与调用者身份确定固定分组，作用于发现列表。显式指定版本 ID 的 API 调用仍使用指定版本；已有任务不会改变版本。候选版本必须构建完成并通过审核，灰度版本与默认版本的可见范围必须一致。下架默认版本会让发现列表暂时隐藏该工具，需发布其他版本或回滚，不会自动发布一个未经选择的新版本。

## 通知

审核通过/驳回、构建结束、异步运行结束和最终回调失败会生成通知。通知菜单支持站内和邮件开关，默认只启用站内通知。邮件只发往已验证邮箱，需已有 SMTP 配置；失败按平方分钟退避，最多尝试 5 次，失败状态保留在通知中。通知邮件只包含事件摘要与对象标识，不包含输入、输出、日志或密钥。SMTP 超时期间可能出现至少一次投递语义，邮件可能重复；站内通知仍可查阅。

## 更强执行隔离

`TOOLDECK_CONTAINER_RUNTIME=runsc` 或 `kata-runtime` 会让运行和构建容器使用宿主机已安装的对应 Docker runtime；不存在时直接失败，不静默退回默认 runtime。本项目不安装这些运行时，宿主机必须先验证内核、cgroup、文件挂载和网络代理兼容性。群晖兼容配置不表示支持这些 runtime。

完整的独立执行节点、控制服务移除 Docker Socket、远程产物传输和 PostgreSQL 多控制节点仍属于后续架构工作。当前 runtime 选项不等同于已经实现控制面与执行面的分离。
