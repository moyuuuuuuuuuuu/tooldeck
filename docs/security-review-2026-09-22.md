# ToolDeck 安全检查（2026-09-22）

范围：ToolDeck 本体，以及工具包上传、构建和运行边界。不包含 ToolDeckApps 工具业务逻辑。本轮为本地源码审计和隔离测试，没有连接或修改线上服务器，没有提交、推送或部署。

## 已修复

| 优先级 | 问题与触发条件 | 修复 |
| --- | --- | --- |
| 高 | 工具 env 可声明 `DOCKER_HOST`、`DOCKER_CONTEXT` 等；执行时工具变量进入宿主侧 Docker CLI 环境，能改变连接目标或配置。 | 禁止 `DOCKER_*` 及部分宿主 Go/TLS 配置变量；平台 secrets 统一使用同一保留名规则；运行时重新检查旧工具的变量和 secrets。 |
| 中 | HTTPS 回调允许 `100.64.0.0/10`、`198.18.0.0/15`、`0.0.0.0/8` 等非公网目标，弱于工具出网代理。实际访问仍取决于网络路由及目标 TLS。 | 回调 URL 和 DNS 解析后的拨号共用现有出网 IP 策略，继续禁止重定向，并连接已检查的 IP。 |
| 低 | ZIP 清单在解压/读取后才检查 128 KiB 上限；忽略第一个 JSON 对象后的内容。 | ZIP 预检即拒绝超大清单；清单只允许一个 JSON 值，尾随空白仍可用。 |

使用新保留名的旧工具会返回校验错误，需要修改变量定义。普通业务变量如 `COZE_API_TOKEN` 不受影响。实际配置值、密钥和部署文件未被修改。

## 工具包检测实际覆盖范围

- 上传需要认证；非管理员不能引用平台 secrets；不同作者不能占用同一工具标识。
- ZIP 检查路径穿越、绝对路径、符号链接/特殊文件、大小写重复条目，限制 2,000 个条目、单文件 64 MiB、总展开容量 128 MiB。
- 清单检查入口、运行时、时长/内存、输入结构、域名白名单和变量名。
- 构建命令及依赖安装在容器内运行；构建 TAR 另有路径、链接、数量和容量检查。
- 执行容器使用 UID 65534、只读根目录、去除 capabilities、禁止提权、默认禁网及受限出网代理；标准模式有进程数、CPU、内存限制。
- 文件下载检查归属或签名；HTML 使用无权限 iframe 和 CSP，Markdown 使用标签/属性白名单。

这些是结构、权限和隔离检查。当前没有自动恶意代码判定、杀毒引擎、工具依赖漏洞扫描或 SBOM 门禁。合法脚本仍可含有恶意逻辑；人工上架审核不阻止作者先构建、调试自己的代码。不能把“上传/构建/审核成功”当成代码安全证明。代码能够读取明确授予它的凭证，日志遮盖也不能阻止恶意代码通过结果或允许的外部服务泄漏凭证。

## 仍需处理的部署与架构风险

1. **高：控制服务挂载宿主 Docker Socket。** 两份 compose 均挂载 `/var/run/docker.sock`。执行容器没有此挂载，但控制服务被攻陷后可能扩大到宿主。公共不可信执行应迁往独立虚拟机/执行节点；`runsc`/`kata-runtime` 选项需先验证安装及兼容性，不能据配置选项认定已启用。[Docker 安全说明](https://docs.docker.com/engine/security/)
2. **高（允许不可信用户执行时）：群晖模式去掉 `--pids-limit` 和私有 cgroup namespace。** CPU 绑定、内存限制不能代替进程数配额。建议公共工具执行使用支持标准隔离的独立宿主。本次未改变兼容参数，以免导致群晖全部执行失败。
3. **中：平台端口默认发布到所有接口。** compose 使用 `${TOOLDECK_PORT:-18088}:8080`；是否从公网可直达未实测。应按代理位置限制监听/防火墙，确保 HTTPS 和入口限流、连接数、上传超时限制。未确认代理网络前不能直接改为 loopback。
4. **中：可用性防护仍有缺口。** `accountRate` 的全站 20 次/分钟共享窗口可被匿名请求耗尽，影响其他用户登录；HTTP 服务只有请求头超时，没有请求体读取期限，上传解压前也没有独立并发准入。后续应结合可信代理配置增加分来源限流、上传并发限制和读取期限，同时保留全站兜底。未进行线上压力测试。

应用 IP 检查还应配合网络层禁止访问内部服务。[OWASP SSRF 防护说明](https://cheatsheetseries.owasp.org/cheatsheets/Server_Side_Request_Forgery_Prevention_Cheat_Sheet.html)

## 验证

- Linux 容器、Go 1.25.14：`go test ./...` 通过。
- 新增 3 组、21 个子用例，覆盖保留环境变量/旧版本定义、回调拨号前阻断及清单边界，通过。
- 在修改前 HEAD 的隔离副本运行同一套新测试，3 组均失败，确认可捕获原有缺口；未向保留地址发送请求。
- npm 生产及全量依赖审计均报告 0 条已知漏洞，仅代表当时漏洞库及锁文件。
- `govulncheck v1.1.4 -show verbose ./cmd/... ./internal/...`：Linux 目标可达漏洞为 0；模块 `golang.org/x/sys v0.34.0` 含 [GO-2026-5024](https://pkg.go.dev/vuln/GO-2026-5024)，影响 Windows 的 `NewNTUnicodeString`，修复版本 v0.44.0。当前目标未导入受影响包，未据此升级整套工具链；Windows 构建需另查。最新版扫描器要求 Go 1.26，因此本轮使用兼容当前工具链的 v1.1.4 查询在线漏洞库。
- 全量 race 检查首次为 80 个顶层测试通过、1 个并发模拟测试超时，没有 DATA RACE 报告。该测试启动被 race 插桩的子进程，默认退出额外等待与其 2 秒期限冲突；设置 `GORACE=atexit_sleep_ms=0` 后，原失败测试与全部新增安全测试的定向 race 复核通过。没有关闭竞态检测，也没有修改测试断言；未声称默认设置下全量 race 已通过。

原始证据在本地忽略目录 `work/security/`。本轮未进行生产镜像漏洞扫描、NAS/公网渗透、真实容器逃逸或压力测试，不能据此判断过去是否已经被入侵。
