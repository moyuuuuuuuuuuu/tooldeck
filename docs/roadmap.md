# ToolDeck 后续改进清单

本轮实现状态与使用说明见 [运行与治理](operations.md)。以下区分已经落地的代码与仍需演进的架构。

## 已实现（本地代码，待部署验证）

- **P0 队列并发**：运行、单用户、构建独立限额；原子领取；工具跨版本并发限制；取消/超时/重启处理；队列和限额指标。默认运行并发 2、单用户 1、构建 1。
- **SQLite 持久化**：实体记录按变化增量写入事务；旧 `state.json` 一次性导入及原文件备份；一致快照导出；控制服务目录独占锁；`StateBackend` 接口。
- **审计与监控**：管理操作审计、操作者与来源、脱敏摘要、结构化日志、运行指标面板和可选 Prometheus 输出。
- **存储治理**：磁盘与目录占用、站点/用户/工具逻辑配额、并发预留、孤儿目录预览和可恢复清理；带本实例标签的停止容器与闲置运行镜像清理。
- **版本管理**：独立默认版本、清单对比、固定用户分组灰度、停止灰度及快速回滚；新版本构建和审核不影响旧默认版本。
- **通知体系**：审核、构建、异步运行、最终回调失败的站内通知；邮件偏好、已验证邮箱投递和失败重试。
- **隔离配置入口**：支持指定宿主机已安装的 gVisor/Kata 等 Docker runtime，失败不回退默认 runtime。

## 仍需推进

1. **真实环境验证**：群晖上验证并发 2 的 CPU/内存压力、Docker 构建与取消钩子、升级/回退演练；SMTP 和 BOS 验证。平台 512 MiB 限制不包含全部工具容器。
2. **独立执行节点**：执行服务、节点认证、任务协议、产物传输与恢复，最终移除控制服务对 Docker Socket 的直接访问。普通 Docker 不作为绝对的不可信代码安全边界。
3. **共享构建缓存治理**：现有 BuildKit 缓存缺乏可靠的项目归属；先引入独立 builder 或缓存命名空间，再开放自动回收，不能直接全局 prune。
4. **多控制节点**：业务查询逐步下沉数据库，接入 PostgreSQL 与分布式领取/租约。当前 SQLite 实现仍采用单控制进程，禁止多个实例同时访问同一数据目录。
5. **长期数据保留**：按业务需求配置运行、通知、审计的归档期限，以及恢复区经过明确确认后的永久清理。
