# ToolDeck 后续改进清单

本文记录当前已确认的生产限制与建议演进顺序，便于更换开发设备后继续推进。它不是已经实现的功能说明。

## P0：运行队列并发

当前 `internal/platform/runner.go` 只启动一个运行 Worker。API Key、OAuth、登录用户和匿名调用共享同一个全局队列，因此 HTTP 请求可以并发入队，但工具任务全局串行执行：

- 每秒选择最早的 `queued` 任务并同步执行，完成后才会领取下一项。
- 全局排队上限为 100。
- 同步非流式调用最多在 HTTP 请求内等待 20 秒，之后返回 `202`，后台仍继续串行执行。
- 节点接口固定报告 `concurrency: 1`。
- 单个长任务会阻塞所有用户和其他工具。

建议增加 `TOOLDECK_WORKER_CONCURRENCY`，但不能只简单启动多个现有 Worker。实现时至少需要：

1. 原子领取任务，确保同一任务不会被多个 Worker 重复执行。
2. 全局并发上限和单用户并发上限，避免一个用户占满执行槽位。
3. 可选的单工具并发上限，保护有第三方接口配额或非幂等行为的工具。
4. 构建队列与运行队列分别设置并发，防止构建占满运行资源。
5. 服务重启、取消和超时场景下正确释放并发槽位。
6. 指标中展示排队数、运行数、等待时间和各类并发限制命中次数。

群晖部署建议初始并发为 2，观察宿主机 CPU、内存和 Docker 压力后再调整。当前平台容器的 `512 MB` 限制不等同于工具执行容器的总资源上限。

## P1：持久化与治理

### 数据存储

核心状态目前保存在单个 `state.json`，通过进程内全局锁保护。数据规模增长后会出现写入放大、查询困难、备份恢复粒度过粗以及无法安全扩展多个控制节点的问题。

建议先迁移到 SQLite，并保留未来接入 PostgreSQL 的存储接口。工具包、输入文件和运行产物继续使用本地目录或 BOS。迁移必须提供旧 `state.json` 的一次性导入、备份和失败回滚。

### 审计日志

记录工具审核、发布、下架、删除、密钥与环境变量变更、用户登录、密码重置等管理操作。建议包含操作者、时间、对象、来源 IP、结果和错误摘要，敏感值不得写入日志。

### 存储空间治理

增加构建缓存、运行镜像、工具包、孤儿容器和孤儿目录的扫描与清理；展示磁盘占用，并支持站点、用户和工具级配额。清理操作应先预览目标，并避免触碰仍被任务引用的文件。

## P2：产品能力

### 工具版本管理

增加默认版本、版本对比、灰度发布和快速回滚。应明确区分“已上传版本”“审核状态”和“当前对外版本”，避免新版本的构建或审核状态影响仍在线的旧版本。

### 可观测性

增加队列长度、成功率、P95 耗时、构建失败率、回调失败率、磁盘空间和在线执行数等后台指标，并提供结构化日志和可选的 Prometheus 指标接口。

### 通知

工具审核通过或驳回、构建完成、异步运行完成、回调最终失败时提供站内通知和可选邮件通知，并允许用户配置通知偏好。

## 长期安全边界

控制服务当前持有 Docker Socket；群晖兼容模式还会降低部分容器隔离能力。普通 Docker 不能作为绝对的不可信代码安全边界。公开承载第三方代码前，应逐步将执行节点拆离控制服务，并评估 gVisor、Kata Containers 或独立虚拟机执行节点。

## 推荐实施顺序

1. 队列并发、原子任务领取和用户级配额。
2. SQLite 数据层迁移。
3. 管理员审计日志与运行监控面板。
4. 存储治理和孤儿资源清理。
5. 工具版本发布与回滚。
6. 通知体系和更强执行隔离。
